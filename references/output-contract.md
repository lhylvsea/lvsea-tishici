# 中文工程化输出契约

本契约把用户提供的“高级 AI 提示词工程师指令”整理成可执行规则，并与 Prompt Master 的工具路由、安全边界和最小充分原则合并。

## 生成结果应覆盖的字段

按任务需要选择字段，不机械填满：

1. **角色**：具体专业身份和与任务直接相关的能力。
2. **背景/上下文**：用户已提供的事实、项目状态、前置条件和目的；未知事实不补造。
3. **任务**：单一、可执行、可验收的动作；多项互斥任务拆分或明确优先级。
4. **输入**：用户将提供的文本、数据、文件、变量、参考图或来源。
5. **受众**：知识水平、关心点、预期收获和需要避免的误解。
6. **输出格式**：结构、语言、长度、语气、文件类型、字段顺序和是否允许解释。
7. **约束/排除项**：范围、不可做的事情、不能改变的事实、禁止偏见或敏感内容。
8. **成功标准**：用可检查的条件定义“完成”，尽量使用二元标准。
9. **示例**：只有格式或风格难以用文字锁定时才加入 2–5 个高因果示例。

## 输出锁

默认结果以 Markdown 呈现并以如下标题开始：

```markdown
# 为[用户目标]优化后的 AI 提示词
```

标题之后直接给可复制 Prompt。不要输出“分析如下”“使用了某某框架”“Token 数量”“评分”或与 Prompt 无关的解释。用户明确要求差异、解释或多个版本时，才解除这条输出锁。

## 显式优化模式

当用户明确要求“优化、改写、打磨、写成正式 Prompt/任务书”时，先输出一条独立可复制的标准 Prompt，再输出不超过 3 行的“改了什么”清单，随后停止，不执行这条 Prompt 描述的任务。清单只说明补齐的字段、显式标记的假设和澄清的指代，不输出隐藏推理或评分。

当用户只要求生成一条 Prompt 时，保持 Prompt-only 输出锁，不因为命中了场景模板或提示词库索引而追加解释。提示词库的索引只负责选择候选，正文必须来自用户提供或已审阅的来源；空白模板不代编。

## 长度和占位符

- 复杂度由任务决定；不以“越长越好”为目标。
- 只在缺失信息会改变结果时使用 `[目标工具]`、`[受众]`、`[输出格式]`、`[项目相对路径]` 等占位符。
- 内容型 Prompt 可使用 `[TONE]`、`[AUDIENCE]`、`[BRAND VOICE]`、`[PRODUCT NAME]`；不得凭空增加更多品牌信息。
- 对未提供但必须确认的事实使用 `[待补充]` 或 `[待核验]`，不伪造示例事实。

## 内部检查，不展示隐藏推理

生成前在内部完成：目标工具确认、任务拆解、关键约束前置、格式可判定性、事实来源边界、敏感信息清理和平台语法检查。最终只保留能帮助目标 AI 正确工作的指令，不要求目标 AI 输出隐藏思维链。

## 最小验收清单

- [ ] 粘贴后目标 AI 能知道要做什么、给谁做、交付什么。
- [ ] 关键上下文、约束和成功标准不依赖本轮对话之外的记忆。
- [ ] 输出格式、长度、语言和语气可直接检查。
- [ ] 没有把推测、来源、数字、版本或凭据伪装成事实。
- [ ] 工具专属语法与模型能力相容。
- [ ] 生成结果没有无关解释，且可以单独复制使用。
