# 目标工具路由与降级规则

本文件把 Prompt Master 的平台差异压缩成运行时决策。只读取与当前目标工具有关的部分；未知工具使用平台中立基线，不伪造专属语法。

## 版本敏感信息

- 模型名称、默认模型、上下文限制和 reasoning/effort 控件会变化；用户要求“最新”或指定未覆盖的模型时，先核对目标平台的官方文档。
- 区分消费端产品、API 和代码代理表面；同一模型家族在不同表面可能有不同的可用工具、参数和默认值。
- 无法核对当前版本时，使用跨版本稳定的行为要求，并把版本敏感项写成待补充信息；不得编造模型 slug、上下文大小、参数或产品能力。

## 先判定任务类别

| 任务 | 优先结构 | 必须关注 |
|---|---|---|
| 简单问答或一次性内容 | RTF | 角色、明确动作、格式 |
| 报告、制度、营销、业务写作 | CO-STAR | 上下文、目标、风格、语气、受众、响应格式 |
| 复杂多步项目 | RISEN / 任务简报 | 步骤、目标状态、范围、验收、停止条件 |
| 创意、品牌、风格迭代 | CRISPE | 角色、洞察、人格、变体 |
| IDE 代码修改 | File-Scope | 文件、函数、当前行为、禁止触碰、完成条件 |
| 自主代理 | ReAct + Stop Conditions / 任务简报 | 起始状态、允许动作、禁止动作、审批点、回滚边界 |
| 图像或视频生成 | Visual Descriptor | 主体、动作、场景、风格、镜头、光线、比例、负面项 |
| 参考图修改 | Reference Image Editing | 保持不变项、仅修改项、参考图附加方式 |
| ComfyUI | ComfyUI | 正面 Prompt、负面 Prompt、checkpoint 与参数分离 |
| 既有 Prompt 拆解/迁移/修复 | Prompt Decompiler | 原始工具、目标工具、保留意图、差异与失败模式 |

## 模型家族适配

- **通用 GPT / Claude / Gemini**：使用清晰角色、上下文、任务和可判定输出格式；复杂任务可要求“先在内部检查约束”，不要求暴露隐藏推理。
- **推理原生模型（o3、o4-mini、DeepSeek-R1、Qwen3 thinking 等）**：只保留目标、约束、输入和验收；删除“逐步思考”“展示思维链”和固定思维预算。
- **Claude 4.x / Claude Code**：前置完整上下文；代理任务写明文件范围、停止条件和人类确认点；不要硬编码思维深度。
- **Gemini**：多模态或长上下文可直接利用；引用任务加入“只引用确定来源，不确定则标记”。
- **Ollama / 本地模型**：若模型名称会改变模板或能力，先询问；系统 Prompt 与用户任务分开，结构保持短而平坦。
- **Qwen 2.5 / 非 thinking 模式**：适合结构化输出；Qwen3 thinking 模式按推理原生模型处理。
- **Llama / Mistral 等开放权重模型**：减少嵌套和长背景，明确角色、任务与格式。
- **Midjourney**：主体、风格、情绪、光线、构图用逗号短语；参数放末尾。
- **DALL·E**：使用自然语言分层描述；未要求文字时明确不要生成额外文字。
- **Stable Diffusion / ComfyUI**：按模型习惯写权重、正负提示词和采样参数；不虚构 checkpoint 能力。
- **Cursor / Windsurf / Copilot**：必须有准确文件/函数锚点、允许范围和完成条件。
- **Claude Code / Devin / Cline / SWE-agent**：必须有起始状态、目标状态、允许/禁止动作、停止条件；涉及删除、依赖、数据库或部署要停下确认。
- **Sora / Runway / Kling 等视频工具**：补充镜头类型、运动、时长、节奏、画幅和连续性约束。

## 不确定时的通用基线

1. 目标未指定：写成平台中立 Prompt，并使用“目标 AI”而不是假定某一厂商。
2. 工具名称已指定但版本未知：只使用跨版本稳定能力，把版本敏感项变成占位符。
3. 目标工具需要模型、checkpoint、文件路径或已有上下文而用户未提供：最多询问 3 个关键缺口；若用户要求立即产出，使用明确占位符并标记待补充。
4. 任何平台说明都不能覆盖安全、隐私、权限、人类确认和用户原始约束。
