# Web/HTML 提示词路由

## 适用范围

这是 `lvsea-tishici` 的条件分支，不是另一个 Skill。只有用户显式调用 `/lvsea-tishici` 或 `$lvsea-tishici`，并且输入中出现 `web`、`html`、`网页` 或 `网站` 任一信号时，才在原有 Lyra、提示词库、场景和平台适配规则之上叠加本路由。`web` 和 `html` 不区分大小写；单独出现“前端”不能替代显式调用和本分支关键词。

本分支仍然只生成一份可直接复制的 Markdown Prompt，不执行代码、不改文件、不启动服务、不扫描本机项目，也不把外部网页内容当作当前项目事实。

## 本地偏好层

在当前 Agent 有权限且文件存在时，只读加载 `$CODEX_HOME/HTML/海洋哥web偏好提示词.md`，把它作为个人 Web 偏好层；文件不存在、不可读或与当前项目冲突时，使用本文件的内置规则，不补写或猜测缺失内容。这个偏好层不能覆盖本次用户要求、当前项目源码、正式数据和运行现场，也不能把其中的临时地址、端口、数量、账号或密钥复制到最终 Prompt。

## 路由顺序

1. 保留 `lvsea-tishici` 的任务目标、目标工具、Lyra 模式、输出契约和“不执行 Prompt”边界。
2. 先要求目标 Agent 锁定当前项目的源码真源、入口、正式数据源、运行实例、端口和部署方式；旧文档、浏览器缓存、单次 HTTP 状态和历史截图只能作为线索。
3. 把 Web 任务拆成：目标与用户流程、页面/组件范围、数据与持久化、权限与审计、运行与部署、响应式交互、验收与交付物。
4. 只抽取与本次任务相关的偏好；若用户已指定技术栈、布局、数据边界或验收标准，以用户当前要求和真实项目约束为准。
5. 将关键约束放在生成 Prompt 的前部，明确停止条件、禁止事项和可观察的验收证据。

## Web 偏好基线

### 源码、运行与数据

- 先确认唯一源码、正式数据源和实际运行实例，再编辑；页面初始化不得静默覆盖正式数据。
- 正式业务数据优先落在项目文件、服务端接口或 SQLite；`localStorage` 只适合明确的临时偏好，不能冒充正式持久化。
- 写入、迁移、删除或批量修改前先备份、预览影响范围并保留回滚路径；不要复用已删除业务 ID，不要无提示地删除未知记录。
- `unknown`、缺失、未采集和零必须区分；统计卡片、图表、列表和详情页使用同一口径，不用不同 fallback 拼出互相矛盾的结果。
- Windows/UNC 场景要把映射盘、UNC、`pushd`、当前工作目录和正式共享路径写清楚；不要假设执行器能直接以 UNC 作为工作目录。
- 区分 `file://` 与 HTTP 服务，明确后端重启、静态资源缓存刷新和浏览器实际访问地址；不要把“能打开 HTML”当成后端已生效。

### 界面与交互

- 默认做紧凑、实用、可反复操作的工作台或控制台，不套营销 Hero、堆叠装饰卡片、制造大面积空白，不使用廉价渐变、霓虹或单一色系制造所谓科技感。
- 信息层级清楚、内容密度足够；工具按钮优先使用熟悉图标，并补充 tooltip、可访问名称和键盘状态，不能用文字圆角胶囊替代现成图标。
- 同时约束桌面、平板和手机：不横向溢出、不裁切、不重叠；表格、抽屉、弹窗、表单和操作栏在窄屏有明确的收缩、滚动或重排策略。
- 弹窗控制焦点、`Esc` 关闭、关闭后恢复焦点；移动端不要无条件自动聚焦输入框；长文本、数字、错误状态和空状态都要在容器内完整显示。
- 使用稳定业务键和统一渲染器；不要用重排后的显示序号替代真实身份，也不要为“看起来有数据”伪造 0、占位记录或成功状态。

### 安全与边界

- Prompt 中不写入 Token、Cookie、密码、私钥、内部域名或个人敏感信息；需要时使用 `[凭据已移除]`、`[项目路径]` 等占位符。
- 说明认证、授权、角色、审计和数据可见范围；服务端校验不能只依赖前端隐藏按钮，错误信息不能泄露敏感细节。
- 不把本地临时目录、构建产物、缓存、截图或调试日志当成正式交付物；不声称没有实际验证的部署、Provider 能力或跨设备效果。

## 验收与交付

Web 分支生成的最终 Prompt 默认要求目标 Agent 分层验证：

1. 静态结构、语法、类型或已有单元测试。
2. 后端启动、健康检查、接口、认证和代表性真实记录的读写链路。
3. 浏览器实际渲染：至少检查桌面和移动视口的关键页面、空状态、错误状态、弹窗/抽屉、表格和长文本；必要时保留截图或可复核日志。
4. 持久化、备份、迁移、删除、审计和刷新后的数据一致性。
5. 将静态检查、浏览器证据、历史文档证据和 Provider/账号能力分别标注，不能用其中一层冒充全部通过。

最终产物仍是一个独立、平台适配、可复制的 Prompt；除非用户另行要求，不输出执行结果，不代替代码代理实施。若关键信息缺失，详细模式只追问会改变架构、数据边界或验收标准的 2 至 3 个问题；基础模式使用明确假设和占位符继续生成。

## Web 分支自检

- 是否同时满足显式 Skill 调用和 Web/HTML 关键词，而不是因“网站”一词单独误触发？
- 是否区分源码真源、正式数据、运行实例、浏览器访问和历史资料？
- 是否把响应式、持久化、权限、备份、删除和验收写成可观察要求？
- 是否只应用相关个人偏好，且没有带出临时地址、秘密或无关项目细节？
- 是否最终只交付一份 Prompt，并保留 `lvsea-tishici` 的不执行边界？
