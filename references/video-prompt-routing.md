# 视频提示词联合路由

本路由把 `lvsea-tishici` 的通用提示词工程与两个互补的视频专项来源连接起来，不复制它们的根入口，也不改变它们各自的调用名。最终仍由 `lvsea-tishici` 负责目标工具适配、事实边界、安全检查和 Prompt-only 交付。

## 来源角色

| 来源 | 运行时调用名 | 主要贡献 | 不负责的部分 |
|---|---|---|---|
| `Emily2040/seedance-2.0` 的 `skills/seedance-prompt/SKILL.md` | `seedance-prompt`（通过 `seedance-20` 父技能解析） | Seedance 2.0 的 T2V/I2V/V2V/R2V 等模式、Director's Read、Subject + Action + Scene + Camera + Light/Style + Audio + Constraints、参考素材角色、镜头连续性和反 Slop 检查 | 不替代通用 Prompt 输出锁，也不自动生成视频或调用 Provider |
| `zhouwei713/seedance-prompt` 的根 `SKILL.md` | `realistic-video-prompting` | 素材来源身份、设备和年代、真实设备缺陷、非完美事件、现场声音、角色一致性和七段式真实感结构 | 不拥有 Seedance 2.0 的模式语法或平台事实；仓库名不是运行时 Skill 名 |

`zhouwei713/seedance-prompt` 的 frontmatter 名称是 `realistic-video-prompting`，因此不能把它误判成第二个同名 `seedance-prompt`，也不能用它覆盖 Emily2040 的入口。

## 运行时解析

- Emily2040 来源优先从已安装的 `seedance-20` 根 Skill 进入，再沿其相对链接读取 `skills/seedance-prompt/SKILL.md` 和所需 `references/`；不额外复制一个同名根目录。
- zhouwei713 来源使用已安装的 `realistic-video-prompting` 直接入口，并按其 Skill 要求按需读取 `references/camera-aesthetics.md`、`references/atmosphere-dictionary.md` 和 `references/anti-ai-checklist.md`。
- 如果某个专项入口在当前 Agent 表面不可发现，继续使用另一个可用来源和 `lvsea-tishici` 的 Visual Descriptor 基线，并明确把缺失专项标记为未调用，不假装已经加载。

## 触发条件

用户显式调用 `$lvsea-tishici` 或 `/lvsea-tishici`，并且任务涉及以下任一信号时，进入联合视频路由：

- 视频生成、文生视频、图生视频、视频到视频、参考图/首尾帧视频；
- Seedance、T2V、I2V、V2V、R2V、FLF2V、镜头、运镜、画幅、时长、现场声音；
- 真实感、去 AI 感、手机随拍、家庭录像、DV、VHS、纪录片、监控或设备缺陷。

只要最终产物是视频生成 Prompt，默认同时参考两个专项来源；若某个来源对当前任务不适用，记录为“不适用”，不要硬塞无关字段。

## 联合流程

1. **先由 `lvsea-tishici` 统一解构**：确认目标工具或视频平台、模式、时长、画幅、参考素材、声音需求、受众、输出格式和安全边界。未知的平台能力不编造。
2. **再由 `seedance-prompt` 定义 Seedance 结构**：确定模式；为 T2V 补齐主体、动作、场景、镜头、物理光线、声音和稳定约束；为 I2V/V2V/R2V/FLF2V 明确参考素材的唯一主角色和不可转移内容；保持一个主要动作、一个主要镜头运动和一个可见终点。
3. **再由 `realistic-video-prompting` 加真实素材层**：当用户要真实、随拍、DV、家庭录像或纪录片感时，补充“谁在拍、什么设备、什么年代、为什么拍”、与设备匹配的物理缺陷、环境响应、现场声音、非完美事件和角色一致性锁定。
4. **最后由 `lvsea-tishici` 合并与压缩**：只保留会改变生成结果的字段，删除重复风格词、空泛质量词和互相冲突的运镜/设备设定，输出一份独立可复制的 Markdown Prompt，不执行生成任务。

## 视频稳定性预算

真实感层必须服从连续性和生成稳定性。用户没有明确要求复杂多镜头或强设备瑕疵时，采用以下默认预算；超出预算要删减，而不是把更多约束继续堆进 Prompt。

1. **道具状态预算**：默认不加道具；主题确实需要时，只加入一个简单、可持续追踪的道具，锁定颜色、形状、持有位置和终点，默认全程携带。不要写抛、踢、滚、丢、捡回、交换或复杂操作；若黄色沙滩球执行“抛起→接住”，接住后应明确“全程抱在手中”。任何状态变化都要写清起点、路径和终点，禁止凭空出现、复制或瞬移。
2. **动作预算**：10–15 秒单镜头默认是一个主动作、最多两个辅助动作和一个收束动作。每个阶段只写一个主要可见动作，连续动作必须有因果连接；删掉不影响主题的并列动作。
3. **镜头预算**：单镜头只保留一条主路径，包括起点、主体关系和终点。不要同时叠加跟拍、推进、环绕、摇臂、变焦和突然转向。人物尤其是儿童需要看清脸部、表情或对焦结果时，从中景起步，可沿同一条路径靠近到中近景；不要把中远景小主体和清晰面部细节同时设为主要求。明确的单镜头使用 3–4 个阶段描述即可；多镜头故事板使用 2–3 个 `Shot`，每个 `Shot` 只保留一个主动作和一个镜头运动。
4. **设备缺陷预算**：默认保留轻微手持倾斜或步行上下浮动作为基础质感，再从自动对焦、曝光修正、轻微运动模糊中最多选择一个事件。果冻效应、滚动快门、广角变形、水雾、眩光、重度失焦和剧烈抖动属于高风险项，不应默认叠加；除非用户明确要求，最多使用其中一个。主动指定的设备事件必须在时间阶段中出现，不能只停留在全局摄像描述。
5. **时间与光线一致性**：只保留一个时间段和主要光线方向，不把“午后”和“傍晚”混在同一段 Prompt。环境事件写成物理链，例如“云影经过，画面短暂变暗，自动曝光恢复到原水平”，不要写成“进入云影后画面变亮”这类反直觉描述。
6. **事件钉点预算**：自动对焦、曝光修正、运动模糊或环境打断都要写成“触发点 → 可见变化路径 → 恢复/终点”，并且只出现一次。例如“跳过泡沫时，自动对焦先落在前景水花，再拉回儿童脸部”。没有明确时间阶段、起点和终点的主动事件直接删除。
7. **未成年人画面关系预算**：儿童使用完整、适龄、非性化服装和安全动作；监护人如只是陪同条件，必须写“画外陪同、不入镜”，避免生成成人手臂或半身。声音写成清脆、短促、年龄匹配的儿童笑声或说话声。目标平台拒绝写实儿童内容时，不通过模糊年龄规避审核，改用明确插画/动画/非写实风格等合规降级。

### 单镜头默认压缩模板

当目标是 WorkBuddy、目标版本未知或用户明确要求连续单镜头时，优先采用：

`模式/时长/连续性 → 主体与一个可追踪道具 → 一个主动作 → 一条主镜头路径 → 3–4 个因果阶段 → 现场声音 → 连续性与负面约束`

把七段式真实感结构用于检查角色、地点、视觉、摄像、时间、音频和目标是否覆盖，不要机械输出七段或 5–7 个事件。默认不写时间码；只有用户或目标表面明确需要时，才使用 3–4 个阶段时间提示，且不要同时混用 `Shot` 标签和硬切语法。

### 联合路由自检

- 是否默认不加道具；若加入道具，是否只有一个简单道具且锁定了颜色、持有位置和终点？状态变化是否只有一条连续链，且没有消失、复制、瞬移或无因果回滚？
- 主动作是否只有一个，辅助动作是否不超过两个，结尾是否有明确收束？
- 摄像是否只有一条主路径，主体尺度是否支持关键脸部/动作可见，设备缺陷是否不超过两个且最多一个高风险事件？
- 每个主动设备事件是否已经落到具体时间阶段，并写清触发、路径和终点？
- 未成年人是否安全、非性化，监护人是否明确画外不入镜，声音是否年龄匹配？
- 时间段、太阳方向、云影、曝光和水面反射是否互相一致？
- 单镜头是否没有硬切或多机位；多镜头是否按 `Shot 1–3` 控制动作和时长？
- 是否删掉了不会改变结果的形容词、第二套运镜和第二套设备美学？

## 冲突优先级

同一字段出现冲突时按以下顺序处理：

1. `lvsea-tishici` 的用户原意、安全边界、凭据保护、平台未知事实和 Prompt-only 输出锁最高；
2. Seedance 2.0 的模式、参考素材绑定、镜头顺序、连续性和平台专属语法由 `seedance-prompt` 负责；
3. 素材来源身份、设备美学、真实缺陷、环境音和去 AI 感细节由 `realistic-video-prompting` 负责；
4. 同一维度不能同时堆两套互相矛盾的设备或镜头逻辑。无法判断时保留用户指定项，其余改为 `[待补充]` 或采用平台中立表达。

## 时间结构规则

- **Seedance 2.0 连续单镜头**：优先写成一个连续段落，描述一个主动作的推进和终点，不把绝对时间码当作 Seedance 语法硬塞进去；若用户提供了复杂时间轴，先压缩成 3–4 个因果阶段。
- **Seedance 2.0 多镜头故事板**：按镜头顺序和切点组织，每个镜头只保留一个主要动作；只有用户明确要求时间码或目标表面需要时间码时才保留时间码。
- **跨模型真实感任务**：可以使用 `realistic-video-prompting` 的七段式覆盖清单和时间轴，但不要把 5–7 个镜头、多个道具状态或多套设备缺陷强行套进一个明确要求单镜头的任务。
- **WorkBuddy 或未知平台**：使用平台中立自然语言；单镜头默认遵守状态、动作、镜头和缺陷预算。若需要时间提示，使用 3–4 个连续阶段，不假定 WorkBuddy 支持 Seedance 专属语法。
- 如果两套规则都可用，Seedance 2.0 的平台镜头语法优先，真实感来源只补充素材身份、设备行为、现场声音和少量可控失误。

## 最终交付

默认只交付一份 Prompt，开头带标题，正文可包含模式、参考角色、主体、动作、场景、镜头、光线、声音、连续性锁和排除项。不要把 `Director's Read`、`POV`、`hidden want`、`素材来源身份` 等内部路由标签原样写进最终 Prompt，除非它们已经被翻译成可见或可听的画面载体。

只有用户明确要求解释、对比或详细模式时，才附极短的来源假设、变更说明或平台限制。没有 Provider、账号、额度或实际生成结果时，不声称已完成模型实跑、效果验证或平台能力验证。

## 典型路由

1. **Seedance 2.0 文生视频**：`seedance-prompt` 定义 T2V、动作终点和镜头；`realistic-video-prompting` 补充拍摄者、设备和自然缺陷。
2. **Seedance 2.0 图生视频**：`seedance-prompt` 负责保留参考图身份和只改变运动/光线/镜头；真实感来源只补充设备行为和现场声音，不能重新描述人物导致漂移。
3. **手机随拍、DV 或家庭录像**：`realistic-video-prompting` 负责真实素材设计；若目标仍是 Seedance 2.0，再由 `seedance-prompt` 将其压缩为对应模式和镜头结构。
4. **Sora、Kling、Runway、Veo 等非 Seedance 工具**：保留真实感层，但删除未经核对的 Seedance 专属语法，回退到 `lvsea-tishici` 的平台中立视频结构。
